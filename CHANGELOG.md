# Changelog

Version = tag; all crates of the workspace carry the same version.

## 0.0.2

### English

- **Window and server (basics, workflow `grundfassung`).** New crates: `fs-activities-server` (the contract `history.capnp` draft 0.1 over a local socket through `fs-rpc` v0.0.2; `capabilities` answers a `CapabilityList` with no capability ids and the contract version `0.1`, and `supportReport`; everything else is `unimplemented`; the server names the contract version itself because the core has none), `fs-activities-client` (connect with the version handshake, `Hello::fetch`, contract check: same main level, minor level of the server not lower), `fs-activities-simple` (the frontend `simple` as a process of its own: name, icon, what works today, what comes, every element locked with "coming soon"; "By me" and "By others" say "The source does not yet deliver who it was"; depends only on the client and fs-components v0.0.25), `fs-activities-bin` (the command `fs-activities`: starter, `serve`, `--version`, `--help`).
- **Starter.** `fs-activities` starts or replaces the server (handshake of `fs-rpc`), asks the frontend to check the contract (`--check`, exit code 3 = does not fit) and falls back to the standard frontend `simple` with a visible message; a missing or unfitting server is said in the window (the reason text comes from fs-rpc and is English only: known, provisional).
- **Pins lifted so the tree holds one source per library:** `fs-objects` v0.0.1 to v0.0.6, `fs-interfaces` v0.0.1 to v0.0.27, new `fs-rpc` v0.0.2, `fs-types` v0.0.1 (through them); the core only changed its pins. `.fs-lock-sources.toml` strict. Minimum Rust 1.89 for the workspace. The hub adapter `fs-activities-hub` is excluded from the workspace for now (`exclude` in `Cargo.toml`): its `fs-registry-client` v0.0.2 (the newest tag) still pins fs-interfaces v0.0.1 and fs-objects v0.0.1, which would give the tree two sources per library; the basics do not need it.
- **CI:** `check.yml` and `release.yml` call fs-release at `v0.0.10`. Linux only (`windows-targets` empty: Unix sockets).
- The real icon (`packaging/net.freesynergy.Activities.png`, `.desktop`, embedded in the window); `fs-activities` depends on the package `fs-activities-simple` (deb `depends`, rpm `requires`).
- Contract: draft (`history.capnp`, not locked). The basics are released with this draft contract.
- **Main view as a preview (rule AUSSEHEN-SOFORT).** The window now opens on a timeline in the look of its models (Nextcloud Activity): filters on the left (all, by program; "By me" and "By others" locked with the reason "The source does not yet deliver who it was"), the search above (Enter), the days as an agenda of the `calendar-view` in the middle. The rows are example data ("Example A/B/C", three days, twelve rows, one summary) marked "Preview" with an info alert at the top and the word "Example" on every row; they live only in `preview.rs` and vanish as soon as the server offers the capability `history`. Hiding the example shows the empty state "Nothing has happened yet". Start and "What comes" stay in the side bar. The title line of the window got the icon at 64 px with the title next to it and the goal below. `--screen main|main-empty|start|coming`.
- Not done: the window shows no real timeline (the core is not wired to the server), no lease (the server keeps running after the window closes until it is stopped or replaced).

### Deutsch

- **Fenster und Server (Grundfassung, Workflow `grundfassung`).** Neue Crates: `fs-activities-server` (der Vertrag `history.capnp` Entwurf 0.1 über einen lokalen Socket mit `fs-rpc` v0.0.2; `capabilities` antwortet mit einer `CapabilityList` ohne Fähigkeits-Kennungen und der Vertragsversion `0.1`, dazu `supportReport`; alles andere ist `unimplemented`; die Vertragsversion nennt der Server selbst, weil der Kern keine hat), `fs-activities-client` (Verbinden mit Versions-Handschlag, `Hello::fetch`, Vertragsprüfung: gleiche Hauptstufe, Nebenstufe des Servers nicht niedriger), `fs-activities-simple` (das Frontend `simple` als eigener Prozess: Name, Symbol, was heute geht, was kommt, jedes Element mit „kommt noch“ gesperrt; „Von mir“ und „Von anderen“ sagen „Quelle liefert noch nicht, wer es war“; hängt nur am Client und an fs-components v0.0.25), `fs-activities-bin` (der Befehl `fs-activities`: Starter, `serve`, `--version`, `--help`).
- **Starter.** `fs-activities` startet oder ersetzt den Server (Handschlag von `fs-rpc`), lässt das Frontend den Vertrag prüfen (`--check`, Rückgabecode 3 = passt nicht) und fällt mit sichtbarer Meldung auf das Standard-Frontend `simple` zurück; ein fehlender oder unpassender Server steht im Fenster (der Grund-Text kommt von fs-rpc und ist nur englisch: bekannt, vorläufig).
- **Pins angehoben, damit der Baum je Bibliothek eine Quelle hat:** `fs-objects` v0.0.1 auf v0.0.6, `fs-interfaces` v0.0.1 auf v0.0.27, neu `fs-rpc` v0.0.2, `fs-types` v0.0.1 (durch diese); der Kern änderte nur seine Pins. `.fs-lock-sources.toml` streng. Mindest-Rust 1.89 für den Arbeitsbereich. Der Hub-Adapter `fs-activities-hub` ist vorerst aus dem Arbeitsbereich ausgenommen (`exclude` in `Cargo.toml`): sein `fs-registry-client` v0.0.2 (der neueste Tag) pinnt noch fs-interfaces v0.0.1 und fs-objects v0.0.1, das gäbe dem Baum zwei Quellen je Bibliothek; die Grundfassung braucht ihn nicht.
- **CI:** `check.yml` und `release.yml` rufen fs-release bei `v0.0.10` auf. Nur Linux (`windows-targets` leer: Unix-Sockets).
- Das echte Symbol (`packaging/net.freesynergy.Activities.png`, `.desktop`, im Fenster eingebettet); `fs-activities` hängt vom Paket `fs-activities-simple` ab (deb `depends`, rpm `requires`).
- Vertrag: Entwurf (`history.capnp`, nicht gesperrt). Die Grundfassung erscheint mit diesem Entwurf.
- **Hauptansicht als Vorschau (Regel AUSSEHEN-SOFORT).** Das Fenster öffnet jetzt auf einer Zeitleiste im Aussehen ihrer Vorbilder (Nextcloud Activity): links Filter (Alle, je Programm; „Von mir“ und „Von anderen“ gesperrt mit dem Grund „Quelle liefert noch nicht, wer es war“), oben die Suche (Enter), in der Mitte die Tage als Agenda des `calendar-view`. Die Zeilen sind Beispieldaten („Beispiel A/B/C“, drei Tage, zwölf Zeilen, eine Zusammenfassung), oben mit einer Info-Meldung „Vorschau“ und auf jeder Zeile mit dem Wort „Beispiel“ markiert; sie stehen nur in `preview.rs` und verschwinden, sobald der Server die Fähigkeit `history` anbietet. Blendet man das Beispiel aus, zeigt sich der Leerzustand „Noch nichts geschehen“. Start und „Was kommt“ bleiben in der Seitenleiste. Die Titelzeile hat das Symbol mit 64 px, den Titel daneben und das Ziel darunter. `--screen main|main-empty|start|coming`.
- Nicht getan: das Fenster zeigt keine echte Zeitleiste (der Kern ist nicht am Server angeschlossen), keine Lease (der Server läuft nach dem Schließen des Fensters weiter, bis er beendet oder ersetzt wird).

### Earlier changes (kept as written)

- Pins `fs-registry` v0.0.2 (was `fs-hub` v0.0.1): crates `fs-registry-client` / `fs-registry`, default socket `registry.sock`; API names (`HubSession`, `HubStatus`, `Manifest`, `connect`, `connect_at`) unchanged.
- Renamed `fs-activity` to `fs-activities` (second step after `fs-history`; ADR 0087, plural rule): crates `fs-activities-core` and `fs-activities-hub`, runtime name in `Capabilities::new` is now `fs-activities-core`. Types, contract and capability IDs stay `history` (wire unchanged).
- The runtime name in `Capabilities::new` (`crates/fs-activity-core/src/repo/provide.rs`) is now `fs-activity-core` (was `fs-history-core`), matching the crate name after the rename `fs-history` to `fs-activity` (ADR 0087). Everything on the wire stays as it was (`history.capnp`, capability IDs `history.*`, `PROGRAM = "history"`, MIME `vnd.freesynergy.history-*`).
